# Формы сущностей

Одна форма на сущность, одинаковая везде: страница, вкладка лаборатории, быстрое создание из другой сущности.
Отличия задаются пропами, а не копией кода. Правка полей или вида формы делается в одном месте.

## Что уже переведено

| Сущность | Форма | Создание «целиком» | Где используется |
|---|---|---|---|
| Наблюдение | `forms/observation-form.tsx` | `lib/create-observation.ts` | страница, вкладка лаборатории, quick-add |
| Прогноз | `forms/prediction-form.tsx` | `lib/create-prediction.ts` | страница, вкладка лаборатории, `AddForecastModal`, quick-add |
| Гипотеза | `components/entities/hypothesis-form.tsx` (`HypForm`) | `lib/create-hypothesis.ts` | страница, «предложения» в лаборатории, боковая колонка, quick-add |

**Не переведены** (отложено владельцем, пока не трогать): вопросы, убеждения, задачи — у них свои формы на страницах
(`QForm`, `WvForm`, `TaskForm`) и свои quick-add модалки, а `onSave` по-старому отдаёт `_links/_images/_pendingFiles`
внутри тела записи. `ResultForm` тоже отдельная.

## Контракт `onSave`

`onSave({ data, links, images, pendingFiles })` (тип `EntitySubmit`, `lib/entity-submit.ts`). Связи, галерея и
inline-картинки из редактора можно создать только после появления `id`, поэтому форма копит их рядом с телом записи, а
не внутри него. Служебных полей с подчёркиванием в `data` нет (на это есть тест).

## Общие пропы

`initial`, `onSave`, `onCancel`, `labs`, `lockedLabId`, `header`, `showLinkPicker` (у `HypForm` — `hideLinksAndImages`),
`submitting`, `error`. Специфичные: `hyps`, `lockedHypothesisId` (прогноз).

## Кирпичики

- `forms/form-parts.tsx` — подписи, футер (`FormFooter`), ошибка (`FormError`), поле с редактором (`RichTextField`),
  пилюли статуса (`StatusPills`), заметка про лабораторию (`LabLockedNote`), хуки `useSubmitExtras` (связи, галерея,
  inline-картинки) и `useRequiredRichText` («текст обязателен»).
- `forms/quick-add-header.tsx` — шапка модалок «создать и привязать»: чип родителя и тип связи.
- `lib/lab-lock.ts` — привязка формы к лаборатории (`lockedLabId`).
- `lib/create-entity-full.ts` — `makeCreateFull(config)`: запись → связи → галерея → подмена inline-картинок.
  Сущность описывается конфигом (`entityType`, `api`, `textField`, `buildUpdate`), а не копией процедуры.
  `buildUpdate` должен отдавать **полное** тело PUT: непришедшее поле PUT может сбросить в умолчание схемы
  (прогнозы бэкенд страхует, остальные сущности нет).
- `lib/use-quick-create-and-link.ts` — общий хук быстрых модалок: создание + привязка к родителю.
- `lib/use-mutation-error-text.ts`, `lib/use-partial-create-notice.ts`, `lib/partial-create.ts` — ошибки и частичные сбои.

## Создание из лаборатории

Форма получает `lockedLabId`: выбора видимости нет, `lab_id` форсируется. Видимость итоговой записи выводит **бэкенд**
из публичности лаборатории (`resolve_lab_attachment`): публичная лаба даёт публичную запись. Поэтому форма не
предлагает выбор, а показывает текст, что получится (`LabLockedNote` ← `use-lab-entity-visibility.ts`; если публичность
неизвестна — нейтральный текст, а не догадка). Подробности и решение владельца — `backend/docs/ACCESS_POLICY.md`
(секция ATTACH). Гипотеза обычного участника остаётся предложением; автопривязка к цели — только у owner/admin.

## Ошибки и частичные сбои

- Падение самой записи → форма остаётся открытой, под кнопками видно сообщение (`error`).
- Запись создана, а поздний шаг упал (связи, картинки, inline-картинки, привязка к цели) → мутация **не** падает, форма
  закрывается, пользователь получает предупреждение. Иначе повторное «Сохранить» создало бы дубль записи. Провалившиеся
  шаги возвращаются в поле `_failedSteps` созданной записи; показывает их `usePartialCreateNotice`.
- Сейчас предупреждение — `window.alert` (уведомлений в проекте нет). Заменить на тост, когда он появится: место
  одно — `use-partial-create-notice.ts`.

Не копировать списки литералами — см. `backend/docs/ENTITY_STATUSES.md`.

## Как добавить форму новой сущности

1. Справочник статусов (`lib/<сущность>-constants.ts` + `Literal` на бэкенде + тест синхронности), если у сущности есть статус.
2. `lib/create-<сущность>.ts` — `makeCreateFull({ entityType, api, textField, buildUpdate })`.
3. Форма из кирпичиков выше; тесты по образцу `observation-form.test.tsx` (контракт `onSave`, блокировка
   лаборатории, ошибка, пустой текст, значения по умолчанию).
4. Потребители: страница (`mutationFn: create<Сущность>Full`, `errorText(create.error)`, `notifyPartial(created)`,
   `create.reset()` при закрытии), вкладка лаборатории (`lockedLabId`, форма рендерится только пока модалка открыта),
   quick-add (`QuickAddHeader` + `useQuickCreateAndLink`).
5. Бэкенд: тест реально сохранённой видимости в публичной и закрытой лабе (`tests/test_lab_entity_visibility.py`).

## Тесты форм: приёмы

Редактор, выбор связей и галерею подменяют заглушками (в jsdom они не нужны); `useMyLabs` — моком списка
лабораторий с `is_public`; перевод — реальным словарём `STRINGS`. Проверяется поведение (что ушло в API, что
показано), а не текст в коде.

## Известные недоделки

- `HypForm` лежит в `components/entities/`, а не в `forms/`, и пока держит собственные кнопки видимости и выпадающий
  список статусов вместо `VisibilitySelect`/`StatusPills` (визуально отличается от наблюдения и прогноза).
- Предупреждения частичных сбоев — `alert` (см. выше).
